# Phone notification / take-away QR test release

User approved publication for phone testing and saving the dedicated VAPID push configuration only in the existing Render backend. No paid plan, Gmail delivery, native iPhone print helper or deferred migrations 032/033 are enabled.

## Scope

- Publish the previously reviewed customer/counter UI, walk-in and later-table-assignment workflows, split-bill clarity, and handoff setting changes that the notification/QR flows integrate with.
- Add per-device administrator/cashier Web Push opt-in, test notification and explicit disable/logout, with private subscription records and an atomic take-away order outbox.
- Add one public take-away QR entry point with isolated private customer visits, daily pickup codes and customer references; never share a cashier or dine-in session among QR users.
- Keep production saved table-visit tools disabled; preserve Android receipt printing and ordinary browser printing. The paused native iPhone receipt handoff remains local only.
- Do not automatically submit test orders, payments or emails to production. Physical iPhone/Android lock-screen receipt of notifications requires user acceptance testing.

## Database safety

Before this release the hosted database contains migrations 001–031 and 034/035, not 032/033/036/037. A fresh private custom-format public-schema backup was restored into an isolated local PostgreSQL cluster without TCP. Applying only 036/037 preserved the signatures of every pre-existing application column and row (110 orders and 38 payments at rehearsal). Production applies the same signature check in one transaction with lock/statement timeouts.

The take-away QR shop switch remains off until publication checks finish. Notification subscriptions require explicit permission and an authenticated admin/cashier; there is no historical-order backfill.

## Publication and rollback

Pause Netlify automatic publishing while the matching Render backend deploys, then verify and publish the completed matching frontend and restore automatic publishing. Render build is `npm install` under `server`, start is `npm start`, and no pre-deploy migration command is configured. Never run the all-migrations schema helper for this release.
