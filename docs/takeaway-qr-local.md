# 独立打包二维码（仅本地，尚未部署）

## 顾客与店员流程

1. 管理员 → 桌位管理 →「查看打包二维码」。二维码仅包含网站的 `/takeaway` 公共入口，可下载 PNG，在本机生成，不调用第三方 QR 服务。
2. 顾客填名字／电话尾号／车牌任一种，不需要完整手机号，也不验证其身份。
3. 每次新的私人点餐记录有独立 table_session/customer_session/token。**大家扫同一二维码，不共用购物车或账单，也不占用实体桌。** 同一浏览器页面刷新沿用原记录。
4. 所有餐点固定打包，仍通过现有菜单价格、选项、售罄、营业时间、暂停接单与幂等下单验证。
5. 成功提交后分配短号，例如 `T003 · 8821`。号码在马来西亚每日内唯一，跨日重新编号；店员核对日期、短号与备注。同名／同尾号不会合并。
6. 顾客成功页显示大字取餐号；柜台散客／最近订单、详情、厨房与取餐队列都带短号和下单时备注。厨房纸单优先印短号＋备注＋打包餐点，不增加长订单号。普通堂食格式不变。
7. 收银、付款、收据和厨房履约沿用原有流程。无桌账单付清且完成出餐后结束本次记录；顾客在 24 小时凭原私人 token 仍能刷新查看，不能往已结束账单继续下单。再次点餐须明确开始新记录。
8. 现有 036 outbox 在同一订单提交事务中排入打包通知；推送继续关闭，必须配置 HTTPS 并获准上线后，用 iPhone/Android 锁屏实测，不等同于已经收到了通知。

## 防混单与恢复

- 公共二维码没有 session token／个人 reference／私人 join key，取餐号也不是授权凭证。没有公开「凭短号查订单」接口。
- 加入入口的随机 UUID 先存在当前 tab 的 sessionStorage，服务端只存 SHA-256；重试只恢复同一客人，不会变成共享访客。下单沿用已有冻结购物车与订单幂等键。
- 扫打包码时若有堂食购物车，必须先处理原车；不会自动清掉原餐点。没有草稿时，明确切换只离开旧会话，不取消旧订单。
- 已提交订单保存不可变的 pickup reference，顾客后来改昵称不会改掉旧厨房单。
- 打包 QR 记录不允许通过「补桌号」并入实体桌，避免暴露独立客人的订单。
- 当前 tab 的浏览器资料若被用户清除，或改用另一台手机／浏览器，不提供跨设备恢复；请向柜台报取餐号核对，不应自动再点一次。
- QR 入口独立开关默认关闭。关闭或暂停仍可查看已有订单与恢复已提交请求；不能新增订单。
- 基础限流为全店每 10 分钟最多 120 个新匿名记录、每私人记录每分钟最多 5 张新订单；同一幂等请求重试不计为新单。**不是完整的反机器人系统**，公开互联网部署前仍需确认限流／防滥用策略。此版本不是配送、线上付款或预约取餐。

## 数据库与本地预览

- 037 依赖 034（允许无桌 table_session），不依赖延期的 032/033；通知另依赖 036。
- 只新增私有入口 hash／过期时间、订单 pickup code/reference/day 和日序列表，不改写旧订单、价格、付款、积分或收据。
- `node server/scripts/upgrade-takeaway-qr.js --local --enable`：先验证私有 pg_dump 备份，只升级独立本地预览库，再开启本地开关；核对订单／付款数量不变。不开启时省略 `--enable`。
- 本地 API 4001，前端 `http://127.0.0.1:4182/takeaway`。生成的本机二维码不能让另一台手机访问这台 Mac 的 localhost，不能当作正式印刷码。
- 没有部署 Netlify／Render，没有推 GitHub，没有更改正式数据库。正式发布需另行批准、备份、升级并配置可达 HTTPS 地址。

## 验证

```
node --test tests/takeawayQr.test.mjs
DINEOS_DATABASE_TESTS=1 DATABASE_URL=postgresql://dineos_local@127.0.0.1:55434/postgres node --test server/tests/takeaway-qr-db.test.js
```

数据库测试用临时数据库和合成数据：两个同名顾客同时扫码、同 join key 并发恢复、不同订单唯一短号、失败订单不占号、不发队列、重试原单、跨客隔离与取消、不可变备注、固定打包、厨房／收银／取餐、合成付款、结束后刷新、暂停接单与通知 outbox。
